# Пробы 1 и 3: карта на ПК и сборка

Пробы из [спецификации прототипа](../../docs/specs/2026-10-prototype.md), «Технология»:

- **Проба 1 «Карта на ПК»** — одна и та же сцена на **PixiJS** (WebGL) и на **CanvasKit**
  (Skia в WASM, как карта «Анамнеза» в веб-сборке), в окне **Electron**.
- **Проба 3 «Сборка»** — Windows-версия и Linux AppImage, собранные на Linux, их размер и
  запуск без сети.

Код пробы в игру как есть не переносится ([`docs/05-process.md`](../../docs/05-process.md), «Пробы»).

## Что на экране

- Больница 60×40 клеток вида сверху, клетка — 1×1 м (как в «Анамнезе», его ADR 0014):
  31 помещение десяти видов цветными зонами, стены полосой по середине стеновых клеток,
  двери проёмом со створкой, 206 предметов мебели простыми формами (кровати, столы, стулья,
  шкафы, аппараты, раковины, цветы). План строится из зерна — одинаковый на любой машине.
- Люди — фигурки «плечи и голова» восьми видов (врач, медсестра, пациенты в своей одежде).
  Каждый идёт по A* (свой простой A* пробы, 4 соседа) в случайное помещение, стоит там 1–4 с
  и идёт дальше.
- Камера: колесо — масштаб вокруг курсора, перетаскивание любой кнопкой мыши — сдвиг.
- Кнопки: реализация, число людей (50/100/200/400), «Вся карта», «Авто-бенч (оба)».
  Счётчик кадров на экране (раз в полсекунды) и в консоли (раз в 5 секунд): кадров в секунду,
  время кадра среднее и p95, время счёта людей, время рисования на CPU.

Как устроено рисование — повторяет «Анамнез» (его `docs/02-architecture.md` §6):

| Слой | PixiJS | CanvasKit |
|---|---|---|
| пол, стены, двери, мебель | один `Graphics`, геометрия строится один раз | запись `SkPicture`, проигрывается каждый кадр |
| люди | `ParticleContainer`: одна текстура-атлас, на кадр — только позиции | `drawAtlas`: та же текстура, RSXform в памяти WASM (`Malloc`) |
| атлас фигурок | общий: рисуется кодом в 2D-холст один раз (`src/sprites.ts`) | тот же |

Обе реализации рисуют один и тот же список фигур (`staticShapes` в `src/hospital.ts`), счёт
людей общий (`src/crowd.ts`), цикл кадров общий (`src/main.ts`).

## Как запустить

Нужен Node.js 22. Все команды — из папки `spikes/map-render/`.

```bash
npm ci                 # зависимости (точные версии — в package.json)
npm run build          # страница в dist/: app.js, index.html, canvaskit.wasm
npm run typecheck      # проверка типов
```

**В браузере.** Странице нужен локальный сервер (с `file://` браузер не даёт загрузить WASM):

```bash
npm run serve          # http://127.0.0.1:8080/
```

Параметры адреса: `?r=pixi` или `?r=ck` — реализация; `&n=200` — людей;
`&bench=1` — авто-бенч текущей реализации, `&bench=all` — обеих подряд;
`&secs=20&warm=2` — секунд замера и прогрева на каждое число людей; `&counts=50,100,200,400`.
Отладка: `&hide=static` или `&hide=people` — не рисовать слой; `&static=bitmap` — пол одной
картинкой вместо фигур; `&aa=1` — MSAA холста у PixiJS (по умолчанию выключен, см. ниже).

**В Electron.**

```bash
npm run electron                    # окно 1600×900 со сценой
npx electron . --bench              # авто-бенч обеих реализаций → bench-electron-*.json, выход
npx electron . --bench --secs 10    # короче
npx electron . --uncapped           # без вертикальной синхронизации (показывает запас)
```

Оболочка (`electron/main.cjs`) отдаёт страницу из `dist/` по своей схеме `app://` — без
dev-сервера; в собранной версии файлы лежат в `app.asar`. Любой запрос в сеть (`http`,
`https`, `ws`) отменяется и считается (`blockedRequests` в итоге). Строгий CSP страницы —
без `unsafe-eval` (у PixiJS для этого подключён `pixi.js/unsafe-eval`, у CanvasKit — только
`wasm-unsafe-eval`). В контейнере без видеокарты нужны `--no-sandbox --probe-swiftshader`
и `xvfb-run`.

**Авто-бенч в Chromium без окна** (Playwright, каждая реализация — в своей вкладке):

```bash
node tools/bench.mjs --capped            # с vsync → results/bench-headless-vsync.json
node tools/bench.mjs                     # без vsync → results/bench-headless-uncapped.json
node tools/bench.mjs --secs 8 --counts 200 --query hide=static --out results/x.json
```

Браузер берётся из `CHROMIUM_PATH` или первый `chromium-*` в `PLAYWRIGHT_BROWSERS_PATH`
(по умолчанию `/opt/pw-browsers`); `playwright-core` 1.56.1 — под сборку Chromium 1194.

Итог бенча — JSON: на каждую реализацию и число людей — кадров в секунду, время кадра
(среднее, p95, максимум), кадры дольше 33 и 100 мс, время счёта людей и A*, время рисования
на CPU, память процессов (в Electron), видеокарта и версия Chromium; плюс время запуска.

## Результаты в контейнере

**Машина:** облачный контейнер, 4 ядра Intel Xeon @ 2,80 ГГц (виртуальные), 16 ГБ, Ubuntu
24.04, **видеокарты нет** — WebGL программный: ANGLE поверх SwiftShader (Vulkan на CPU).
Chromium 141.0.7390.37 (Playwright 1.56.1), Electron 44.5.1 (Chromium 152.0.7977.130).
Пакеты: pixi.js 8.22.0, canvaskit-wasm 0.42.0, electron-builder 26.15.3, esbuild 0.28.2,
TypeScript 6.0.3.

> **Абсолютные числа — не про ПК владельца.** Здесь вся работа видеокарты — на тех же
> четырёх ядрах процессора. Ценно другое: сравнение PixiJS и CanvasKit на одной сцене и
> стоимость на стороне CPU (счёт людей, A*, подготовка кадра).

Замер 20 с после прогрева 5 с на каждое число людей, с вертикальной синхронизацией;
время кадра — интервал между кадрами, мс, среднее / p95.

| Реализация | Людей | Chromium без окна, 1280×720: к/с | кадр, мс | Electron под xvfb, 1600×900: к/с | кадр, мс | рисование на CPU, мс (Electron) |
|---|---:|---:|---:|---:|---:|---:|
| PixiJS | 50 | 11,3 | 88 / 167 | 8,2 | 121 / 233 | 0,6 |
| PixiJS | 100 | 11,6 | 87 / 167 | 8,4 | 119 / 217 | 0,4 |
| PixiJS | 200 | 10,9 | 92 / 167 | 8,5 | 117 / 217 | 0,5 |
| PixiJS | 400 | 11,3 | 88 / 183 | 8,3 | 121 / 217 | 0,4 |
| CanvasKit | 50 | 22,7 | 44 / 83 | 16,5 | 61 / 100 | 2,2 |
| CanvasKit | 100 | 21,7 | 46 / 83 | 16,0 | 62 / 100 | 2,1 |
| CanvasKit | 200 | 22,5 | 44 / 67 | 16,0 | 63 / 83 | 2,1 |
| CanvasKit | 400 | 21,7 | 46 / 83 | 15,3 | 65 / 100 | 2,1 |

Полные данные — `results/*.json`. Кадров дольше 100 мс за 20 с: PixiJS 55–115, CanvasKit 0–9.

**Из чего складывается кадр** (Chromium без окна, 200 человек, vsync, 8 с):

| Что рисуется | PixiJS, к/с | CanvasKit, к/с |
|---|---:|---:|
| всё | 10,9 | 22,5 |
| только люди (`hide=static`) | 41,5 | 42,9 |
| только пол, стены, мебель (`hide=people`) | 11,1 | 21,4 |
| пол одной картинкой (`static=bitmap`) | 12,5 | 25,6 |
| всё, PixiJS с MSAA (`aa=1`) | 7,0 | — |

**Стоимость на CPU** (не зависит от видеокарты, поэтому переносится на ПК с поправкой на
процессор):

- счёт 400 людей вместе с поиском путей — **0,1–0,2 мс на кадр**; один поиск A* на сетке
  60×40 — 0,04–0,1 мс в среднем;
- подготовка кадра на CPU: PixiJS — **0,3–0,6 мс**, CanvasKit — **1,8–2,2 мс** (проигрывание
  записи пола в WASM; с полом-картинкой — 0,7 мс). Число людей на это почти не влияет.

**Запуск и память Electron** (под xvfb, программный WebGL):

- от старта процесса до первого кадра — **0,8–1,0 с** (`processStartToFirstFrameMs`);
  загрузка и запуск CanvasKit WASM — 0,2–0,4 с, создание PixiJS — 0,04–0,09 с;
- память всех процессов (рабочий набор) — **560–590 МБ**: окно ~150 МБ, главный процесс
  ~165 МБ, GPU ~190 МБ (здесь в нём и программный рендер), служебные ~85 МБ. Рабочие наборы
  считают и общие страницы, поэтому сумма завышена.

**Что видно.**

1. Число людей до 400 на время кадра почти не влияет у обеих: 400 фигурок одним пакетом —
   дёшево. Дорог неподвижный слой — заливка всей площади экрана.
2. В программном WebGL PixiJS рисует тот же пол **вдвое медленнее** CanvasKit, и даже пол
   одной текстурой почти не помогает (11 → 12,5 к/с). Значит, дорог не объём геометрии, а
   работа на каждую точку экрана: пиксельный шейдер пакетов PixiJS (выбор из нескольких
   текстур) на процессоре дорог, у Skia шейдер прямоугольника проще. На настоящей видеокарте
   эта разница почти исчезает — это догадка, проверить можно только на ПК.
3. MSAA холста у PixiJS в программном WebGL стоит ещё 35 % — по умолчанию он выключен у обеих
   (Skia сглаживает края фигур сама).
4. Без vsync (`results/bench-headless-uncapped.json`) числа рваные: первые секунды кадры только
   копятся в очереди GPU-процесса, потом очередь сбрасывается рывками. Для сравнения
   пригодны только замеры с vsync; без vsync — смотреть только на ПК с видеокартой.

## Сборка (проба 3)

```bash
npm run dist:linux     # release/BolnitsaProbe-0.0.1-linux-x86_64.AppImage и …-linux-x64.tar.gz
npm run dist:win       # release/BolnitsaProbe-0.0.1-win-x64.zip и …-win-x64.exe (portable)
```

Обе команды сначала собирают страницу (`npm run build`), потом electron-builder 26.15.3.
Electron и инструменты сборки (AppImage, NSIS, 7-Zip) скачиваются при первой сборке и
кэшируются в `~/.cache/electron` и `~/.cache/electron-builder`; дальше сеть не нужна.

| Файл | Размер | Что это |
|---|---:|---|
| `…-win-x64.zip` | 137,5 МБ | папка с `BolnitsaProbe.exe`: распаковать и запустить |
| `…-win-x64.exe` (portable) | 89,1 МБ | один файл; при каждом запуске распаковывается во временную папку |
| `…-linux-x86_64.AppImage` | 119,7 МБ | один файл, Linux x64 |
| `…-linux-x64.tar.gz` | 114,0 МБ | папка, Linux x64 |
| распакованная Windows-версия | 329 МБ | из них страница пробы — `app.asar` 8 МБ (WASM CanvasKit 7,3 МБ, JS 0,7 МБ) |

Сборка в контейнере: Linux — 4,5 мин, Windows — 6 мин (почти всё время — сжатие на 4 ядрах).

**Windows из Linux без wine.** Документация electron-builder («Multi Platform Build»)
требует для Windows-целей на Linux Wine 2.0+ (Mono — только для Squirrel.Windows). На деле
в 26.15.3:

- **zip и portable собираются без wine**, если `win.signAndEditExecutable: false` (так в
  `package.json`). Цена: у `.exe` нет своей иконки и сведений о версии (стоит иконка и
  «Electron» по умолчанию), подписи нет;
- `signAndEditExecutable: true` (иконка, версия, подпись) — падает: `spawn wine ENOENT`;
- **установщик NSIS** (`--win nsis`) — тоже падает на `spawn wine ENOENT` даже без правки
  ресурсов. Поэтому установщик отключён; portable сам основан на NSIS, но wine ему не нужен.

Проверено: собранный AppImage запускается в пространстве имён **без сети** (`unshare -n`),
грузит страницу из `app.asar`, проходит авто-бенч, отменённых запросов — 0, итог пишет рядом
с AppImage. Windows-версию здесь запустить негде (нет ни Windows, ни wine) — `file` подтверждает
`PE32+ executable (GUI) x86-64` и `Nullsoft … self-extracting archive` у portable.

**Каким будет workflow в CI** (не добавлен: `.github/` — путь владельца; по ADR студии 0019):

- запуск — только на тег `v*`, без ручного запуска и без сборки на слияние; `runs-on: ubuntu-24.04`;
- шаги: checkout → setup-node 22 с кэшем npm → кэш `~/.cache/electron` и
  `~/.cache/electron-builder` → `npm ci` → `npm run build` →
  `npx electron-builder --linux --win --publish never` → загрузка `release/*.AppImage`,
  `*.tar.gz`, `*-win-x64.zip`, `*-win-x64.exe` в черновик релиза на этот тег;
- если нужен установщик NSIS и иконка у `.exe` — шаг `sudo apt-get install -y wine64`
  перед сборкой и `signAndEditExecutable: true` (или отдельная сборка Windows на
  `windows-2025` — это отступление от правила `ubuntu-24.04`, решение владельца);
- подпись Windows-сборки (сертификат) и Steam — отдельные решения, не сейчас.

## Вывод

**Electron годится.** Окно открывается за ~1 с до первого кадра, работает без сети и без
dev-сервера, страница в `app.asar`, сборки для Windows (zip, portable) и Linux (AppImage,
tar.gz) получаются на Linux одной командой, 90–140 МБ. Цена — память: ~0,5 ГБ на процессы
Chromium даже у пустой сцены; для ПК-игры приемлемо. Electron 44 больше не собирает 32-битные
Windows — для Steam это не важно.

**Карта: предварительно — CanvasKit.** В контейнере он вдвое быстрее PixiJS по работе
«видеокарты», ровнее (почти нет кадров дольше 100 мс) и даёт перенос из «Анамнеза» как есть:
`SkPicture` пола, `drawAtlas` людей, рисунки ЭКГ и рентгена — тот же Skia. Цена — 7,3 МБ WASM,
0,2–0,4 с на запуск и ~2 мс CPU на кадр против ~0,4 мс у PixiJS (лечится полом-картинкой:
0,7 мс). У PixiJS плюсы — лёгкий, дешевле на CPU, богаче готовыми вещами (текст, события,
фильтры). Оба на CPU укладываются с большим запасом: 200 людей с A* — доли миллисекунды.
**Окончательно решит замер на ПК владельца**: если обе дают 60 к/с при 200–400 людях — берём
CanvasKit ради переноса из «Анамнеза»; если CanvasKit не держит 60, а PixiJS держит — PixiJS.

## Что осталось проверить на ПК владельца

- Настоящая видеокарта: 60 к/с при 200 и 400 людях, p95 кадра, разница PixiJS и CanvasKit;
  то же с `--uncapped` — запас сверх 60.
- Что Windows-сборка вообще запускается: zip и portable, без сети, без установки чего-либо;
  предупреждение SmartScreen о неподписанном `.exe`; время запуска portable (распаковка).
- Масштаб экрана Windows 125–150 % (`devicePixelRatio` больше 1 — точек втрое больше).
- Память и время запуска на настоящем Windows.
- Слабый ноутбук (критерий прототипа — не меньше 30 к/с) — когда владелец его выберет.

## Инструкция для владельца

1. Распакуйте `BolnitsaProbe-0.0.1-win-x64.zip` в любую папку (например, на рабочий стол).
2. Запустите `BolnitsaProbe.exe` (Windows может спросить «Запустить всё равно?» — сборка не подписана).
3. Нажмите вверху «Авто-бенч (оба)» и ничего не трогайте ~4 минуты; окно не сворачивайте.
4. Когда появится «Готово. Итог сохранён: …», закройте окно.
5. Пришлите файл `bench-electron-….json` из той же папки и напишите модель компьютера (или ноутбука) и монитора.
