# Как ведётся работа

Общий порядок — в уставе студии
([`docs/04-process.md`](https://github.com/Nefeste/gornitsa/blob/main/docs/04-process.md)):
документы в репозитории, спецификация до кода, ADR, ветки `claude/…`, PR, CI на PR. Здесь —
только особенности «Больницы» как первой ПК-игры студии.

## Ветки, слияние, CI

- Работа — в ветках `claude/<задача>`, в `main` — через PR. Кто сливает — по классам
  изменений (ADR студии [0018](https://github.com/Nefeste/gornitsa/blob/main/adr/0018-change-classes-automerge.md));
  пути владельца — в [`.github/CODEOWNERS`](../.github/CODEOWNERS).
- Проверки на PR (`pr.yml`, ADR студии [0019](https://github.com/Nefeste/gornitsa/blob/main/adr/0019-ci-on-pr.md)):
  сборка и валидатор базы, типы, тесты и сборка страницы игры — те же команды, что в `AGENTS.md` («Commands»). Electron
  там не скачивается: установщики собирает только сборка по тегу.
- Сборка для ПК — только на тег версии `vX.Y.Z`, как APK у мобильных игр; ручного запуска
  нет. Тег ставит владелец. Workflow — [`.github/workflows/build.yml`](../.github/workflows/build.yml):
  Electron, Windows (zip и portable `.exe`) и Linux (AppImage и tar.gz) — всё на
  `ubuntu-24.04`, без wine; файлы — в релиз на тег, версии 0.x — пре-релизы. Тег сверяется с
  версией в корневом `package.json`: `v0.0.4` при `0.0.3` останавливает сборку.
- С версии `0.0.3` собирается **игра из корня** (оболочка и 3D-вид над движком,
  [`specs/2026-10-shell-3d.md`](specs/2026-10-shell-3d.md)); файлы релиза — `Bolnitsa-<версия>-win-x64.zip`,
  `…-win-x64.exe`, `…-linux-x86_64.AppImage`, `…-linux-x64.tar.gz`. `Bolnitsa` — рабочее имя файлов, марку решит
  владелец. Пробы (`spikes/map-render` — `v0.0.1`, `spikes/render-3d` — `v0.0.2`) остаются в репозитории, но больше
  не собираются. Установщика NSIS и своей иконки у `.exe` нет: без wine они не собираются
  (`spikes/map-render/README.md`, «Сборка»).

## Сборка игры у себя

```bash
npm ci                 # с Electron (~100 МБ); для одних проверок — ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci
npm run build          # база + страница и поток расчёта → dist/
npm run electron       # окно игры
npm run dist:linux     # AppImage и tar.gz → release/
npm run dist:win       # zip и portable .exe → release/ (из Linux, без wine)
```

`dist/` и `release/` в репозиторий не попадают. Модели лежат в `assets/models/` готовыми; заново их делает
`npm run assets -- <папка с наборами>` из исходных наборов CC0 (откуда — `assets/LICENSES.md`): файлы выходят те же
до байта, хэши — в `assets/models/sources.json`.

## Пробы

Код проб живёт в `spikes/<имя>/`, у каждой — свой `README.md`: что проверяли, как запустить,
что вышло. Итог проб — ADR проекта. Проба остаётся как была; её код в игру переносится копированием с пометкой
`// из spikes/<имя>: <путь>` в первой строке (и что изменено) и доводится уже в игре.

## Копии из «Анамнеза»

Движок и медицинская база переносятся копированием (ADR студии 0002) с пометкой источника и
коммита в первой строке файла. Список копий находится поиском по строке `// из anamnez:`.
Исправление в скопированном — задача перенести его и в «Анамнез».

## Версии

По уставу. Первая версия — прототип для игры владельца; номер — `0.1.0`. До неё — сборки `0.0.x`: пробы и оболочка;
что в каждой — в разделе версий корневого [`README.md`](../README.md).
